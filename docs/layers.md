# Хранение растровых слоёв

Размер документа задаёт видимую область композиции и экспорта. Содержимое слоёв
не ограничено этой областью; изменение размеров документа его не обрезает.

`Layer.pixels` — `SparsePixels`: смещение в координатах документа и таблица
физических плиток RGBA8 размером 64×64. Ключи плиток знаковые, в локальных
координатах слоя. Отсутствующая плитка прозрачна; пустой слой не выделяет
память под растр документа. Плитки разделяются через `Arc`, запись копирует
только изменяемую плитку, если она удерживается историей.

- Кисть и заливка работают в пределах документа, записывая пиксели через
  смещение слоя. Мазок может расширить набор плиток независимо от исходного
  размера вставленного изображения.
- Перемещение целого слоя меняет только смещение, с округлением до пикселя
  при применении. Пиксели сохраняются и за отрицательными координатами.
- Предпросмотр трансформации целого слоя использует GPU-плитки; между
  разнесёнными фрагментами не выделяется сплошной прозрачный буфер.
- Масштабирование и поворот целого слоя пересчитывают области, покрытые
  преобразованными исходными плитками. Выделенный фрагмент использует
  временный плотный буфер выделения. Оба пути сохраняют результат за холстом.
- Undo мазков хранит прежние и новые версии затронутых плиток, включая
  отсутствие плитки. После окончания операции полностью прозрачные
  затронутые плитки освобождаются. Undo трансформаций разделяет плитки
  снимков слоя, не копируя всё содержимое.

Обычный GPU-кэш пока содержит текстуру размером с документ для каждого слоя.
Логические dirty-плитки документа определяют участки загрузки; каждый участок
собирается из физических плиток слоя отдельно. Целый слой после каждого
мазка не упаковывается. Память CPU независима от площади пустых промежутков,
а обычный GPU-кэш всё ещё зависит от размера документа и числа слоёв.

## Файл проекта

Workspace записывает версию 6 и читает версии 5 и 6. Ресурсы библиотеки
записываются в lossless WebP; существующие PNG также читаются.
Растр слоя хранится в `.tiles`. Поле `compression` в описании слоя в
`manifest.json` определяет способ хранения всего потока байтов этого слоя:

- Поле отсутствует или равно `"none"`: исходный поток без сжатия.
- `"zstd"`: весь поток сжат Zstd без потерь, уровень записи 3.
- Неизвестное значение: ошибка открытия с именем слоя и кодека.

При сохранении новые и изменённые слои записываются с
`"compression": "zstd"`. Неизменённые слои повторно не записываются и сохраняют
прежний способ хранения, включая сырые данные без сжатия.
Инкрементальное сохранение дописывает данные: прежние записи остаются в
контейнере до Optimize. Optimize сжимает сырые слои сохранённой версии,
обновляет манифест и удаляет устаревшие записи; несохранённые правки в памяти
при этом не записываются. Уже сжатые слои копируются без перекодирования.
Поддержка чтения старых кодеков должна сохраняться при добавлении новых.

После распаковки структура потока прежняя: два little-endian `i32` смещения, затем
записи `(tile_x: i32, tile_y: i32, rgba: [u8; 16384])` до конца файла.
Координаты записываются в отсортированном порядке. Сохраняются все плитки,
включая лежащие вне документа. Экспорт PNG/JPEG/WebP ограничен холстом.

## Превью и загрузка по требованию

Манифест каждого документа и ассета содержит необязательное поле `preview` —
путь к миниатюре 84×84 в lossless WebP. Миниатюры находятся в
`/previews/documents/{id}.webp` и `/previews/assets/{id}.webp`.

`Workspace::open` читает манифест и миниатюры, оставляя полные пиксели на диске.
Приложение загружает слои активного документа при открытии проекта; остальные —
при переключении на документ. Ассет декодируется при просмотре или вставке
перетаскиванием. Уже загруженные данные остаются в памяти и используются повторно.

В старых проектах без `preview` миниатюры однократно строятся из полных данных;
полные буферы после этого освобождаются. Сохранение или Optimize записывает
миниатюры, и следующие открытия используют их без декодирования всех изображений.

Сохранение пропускает неизменённые незагруженные данные; запись в новый файл
копирует их в исходном кодировании. Optimize сохраняет превью сохранённой версии,
не подменяя их несохранёнными изменениями. Снимок исходного контейнера удерживается
до загрузки данных, в том числе для удалённых документов в undo. На Windows
атомарная замена использует ReplaceFileW, чтобы такие читатели продолжали работать.

## Проверка

`cargo test --offline` проверяет хранение, рисование, трансформации, историю,
сохранение и экспорт. Проверка реального GPU запускается отдельно:

```text
cargo test --offline tiled_preview_uploads_and_composes_in_layer_order -- --ignored
```
