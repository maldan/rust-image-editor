# Формат файла проекта (`.mgimg`)

Проект — один файл `.mgimg`: контейнер **MGFL** через `mega-file`.
Поверх него лежит схема приложения с виртуальными путями и JSON-манифестом.

Код: `src/workspace.rs` (схема и I/O), `src/safe_save.rs` (безопасная запись),
`src/project.rs` (модель документа в памяти).

## Контейнер

`mega-file` даёт:

- виртуальные пути (`/manifest.json`, `/assets/...`);
- тип записи (`kind`);
- CRC-32C;
- пакетную запись;
- **append-only** обновления при обычном Save;
- компакцию через **Optimize** (`mega-file::optimize`).

Обычный Save в тот же путь дописывает только изменённые записи.
Save As / первое сохранение пишет новый архив целиком во временный файл и
атомарно подменяет целевой (на Windows — `ReplaceFileW`, чтобы открытые
читатели старого снимка не ломались).

## Дерево внутри архива

```text
/manifest.json                          схема workspace (JSON)
/assets/{id}.webp                       ресурс библиотеки (lossless WebP; старые PNG читаются)
/videos/{id}.mp4                        видеоресурс
/documents/{doc_id}/layers/{i}.tiles    растр слоя i (тайлы 64×64)
/documents/{doc_id}/layers/{i}.timeline held-drawings анимации (только type=animation)
/previews/assets/{id}.webp              миниатюра 84×84
/previews/videos/{id}.webp              постер видео (если есть)
/previews/documents/{id}.webp           миниатюра документа
/graphs/{id}.json                       шаблон графа (ссылки, без пикселей)
```

Индексы слоёв `{i}` — позиция в массиве `layers` манифеста (0-based).

## Манифест

Путь: `/manifest.json`  
Kind: `mega-image-editor/manifest+json`

```json
{
  "format": "mega-image-editor",
  "version": 11,
  "active_document": 0,
  "assets": [
    /* AssetMeta */
  ],
  "videos": [
    /* VideoMeta */
  ],
  "documents": [
    /* DocumentMeta */
  ],
  "graphs": [
    /* GraphMeta */
  ]
}
```

Пишется версия **11** (добавлены видеодокументы). Читаются **5–11**. Старые файлы без `graphs` открываются с пустым списком (в UI остаётся Graph 1).

### AssetMeta

| поле              | смысл                                          |
| ----------------- | ---------------------------------------------- |
| `id`, `name`      | идентификатор и имя в библиотеке               |
| `width`, `height` | размер                                         |
| `path`            | путь к полному изображению                     |
| `preview`         | путь к миниатюре (опционально в старых файлах) |

### VideoMeta

| поле         | смысл                     |
| ------------ | ------------------------- |
| `id`, `name` | идентификатор и имя       |
| `path`       | обычно `/videos/{id}.mp4` |
| `preview`    | постер WebP, если есть    |

### DocumentMeta

| поле              | смысл                                                                                                                 |
| ----------------- | --------------------------------------------------------------------------------------------------------------------- |
| `version`         | схема записи документа (сейчас 1); у старых файлов отсутствует и читается как 1; неизвестная версия — ошибка загрузки |
| `type`            | `"image"` (по умолчанию), `"animation"` или `"video"` (см. ниже)                                                      |
| `animation`       | настройки таймлайна (fps, length, frame, camera, play_start/end); есть только у animation                             |
| `video`           | настройки видеодокумента; есть только у video (см. ниже)                                                              |
| `id`, `name`      | документ                                                                                                              |
| `width`, `height` | размер холста (видимая область)                                                                                       |
| `active_layer`    | индекс активного слоя                                                                                                 |
| `layers`          | список `LayerMeta`                                                                                                    |
| `preview`         | миниатюра документа                                                                                                   |

`type` и наличие `animation` должны совпадать. У animation у каждого слоя
обязан быть `timeline`.

#### Видеодокумент (`type = "video"`)

Код: `src/video_document_file.rs` (формат), `src/video_document.rs` (`to_record` / `from_record`).
Записи видеодокументов идут в `documents` **после** всех растровых, чтобы индексы
манифеста и `active_document` не сдвигались. Манифест версии 11; приложения до 11 такой файл не откроют.

Видеодокумент — тот же `DocumentMeta`, но вместо растровых слоёв у него поле
`video` с настройками. Правила:

- `type = "video"` ⇔ есть `video`; `animation` отсутствует.
- `layers` пустой или отсутствует, растровых файлов `.tiles` нет.
- Пиксели не хранятся. Видео подключаются ссылками на `VideoMeta.id`.
- Состояние вида (зум, скролл, выделение, скрытые дорожки) не сохраняется.
- Все имена полей внутри `video` (включая клипы и эффекты) — **camelCase**
  (`laneCount`, `sourceIn`, `scalePercent`, `startSeconds`). В Rust это
  `#[serde(rename_all = "camelCase")]` на каждой структуре.

Минимальный состав `video` (остальные настройки добавляются позже,
неизвестные поля читатель игнорирует):

| поле        | смысл                                                                                                                                                                             |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `version`   | версия схемы самого `video` (сейчас 1), независима от `DocumentMeta.version`: позволяет поменять хранение видео, не трогая запись документа; неизвестная версия — ошибка загрузки |
| `fps`       | частота кадров документа                                                                                                                                                          |
| `duration`  | длительность, секунды                                                                                                                                                             |
| `laneCount` | число дорожек (lane)                                                                                                                                                              |
| `background` | цвет фона холста как массив RGBA в диапазоне 0–1. Поле необязательно, по умолчанию используется тёмный фон |
| `clips`     | список клипов                                                                                                                                                                     |

Клип: `asset` (`VideoMeta.id`), `lane`, `start`, `sourceIn`, `sourceOut`
(секунды), `scalePercent`, `position`, `effects` (настройки эффектов).
Время хранится в секундах. `position` — как в редакторе (доля документа, `0.5` — центр).

Загрузка и валидация:

- Неизвестная `video.version`, `fps` вне `1..=240`, `laneCount` вне `1..=1024`, клип с
  `lane >= laneCount`, `sourceOut <= sourceIn` или не конечными числами — ошибка загрузки проекта.
- Клип, чей `asset` отсутствует среди видео проекта, пропускается (в статусе пишется сколько).  
  При следующем сохранении он из файла пропадёт.
- `source_duration` не хранится: берётся из ассета, а пока ассет не проинспектирован
  в фоне — равен `sourceOut`.
- Несохранённые правки видеодокумента помечают проект изменённым (сравнение со снимком
  сохранённого состояния); зум, скролл, playhead и выделение на это не влияют.

##### Эффекты клипа (`clip.effects`)

Массив объектов. Общие поля вынесены наружу, настройки конкретного эффекта лежат в `data`:

```json
"effects": [
  { "type": "fadeIn",  "enabled": true, "data": { "seconds": 1.0, "easing": "smoothstep", "scale": 1.0 } },
  { "type": "fadeOut", "enabled": true, "data": { "seconds": 0.5, "easing": "linear", "scale": 0.8 } },
  { "type": "move",    "enabled": true, "data": { "startSeconds": 0.0, "seconds": 2.0, "easing": "easeInOut",
                                                  "from": { "x": -15, "y": 0 }, "to": { "x": 0, "y": 0 } } }
]
```

| поле      | смысл                                      |
| --------- | ------------------------------------------ |
| `type`    | `"fadeIn"`, `"fadeOut"` или `"move"`       |
| `enabled` | эффект включён (по умолчанию `true`)       |
| `data`    | настройки эффекта, схема зависит от `type` |

`data` по типам:

| type                | поля                                                                                                                              |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `fadeIn`, `fadeOut` | `seconds` ≥ 0 — длительность; `easing`; `scale` в `[0.01, 100]` — масштаб в полностью прозрачной точке (1.0 = без масштаба)       |
| `move`              | `startSeconds` ≥ 0 — начало от старта клипа; `seconds` ≥ 0 — длительность; `easing`; `from`, `to` — смещение `{x, y}` в процентах |

`easing`: `"linear"` (по умолчанию), `"easeIn"`, `"easeOut"`, `"easeInOut"`, `"smoothstep"`.

Правила:

- Не больше одного эффекта каждого `type` на клип. Порядок в массиве смысла не имеет: непрозрачность берётся по минимуму, масштаб перемножается, смещение складывается.
- Хранятся только настройки. Запечённые кадры (`bake`) пересчитываются при загрузке.
- Эффект с невалидным `data` (не конечные числа, значения вне диапазонов) при загрузке отбрасывается, как это делает `settings_valid` при добавлении.
- Неизвестный `type` читатель не ломает: эффект пропускается при отрисовке, а `data` сохраняется как есть и пишется обратно, чтобы файл не терял данные из более новой версии.
- Новые эффекты добавляются новым значением `type` со своей схемой `data`; существующие схемы меняются только через `video.version`.

### GraphMeta

| поле         | смысл                                                  |
| ------------ | ------------------------------------------------------ |
| `id`, `name` | идентификатор (`g_1`) и имя в Library                  |
| `version`    | схема json графа (сейчас 1); дублируется в корне файла |
| `path`       | обычно `/graphs/{id}.json`                             |

Файл графа — шаблон: ноды (`kind` + `data`), линки, вид. Пиксели не хранятся,
только id документа/ассета. Слой в v1 не пишется.

### LayerMeta

| поле                         | смысл                                                                                                  |
| ---------------------------- | ------------------------------------------------------------------------------------------------------ |
| `id`                         | строковый id слоя (`l_<hex>`); пока ни на что не ссылается, у старых проектов назначается при загрузке |
| `z`                          | глубина, конечное число в `[-10, 10]`                                                                  |
| `name`, `visible`, `opacity` | UI-свойства (`opacity` по умолчанию 1.0)                                                               |
| `aiMetadata`                 | необязательные метаданные ИИ: `prompt` и `model`                                                       |
| `path`                       | путь к `.tiles`                                                                                        |
| `compression`                | `"none"` / отсутствует, или `"zstd"`                                                                   |
| `timeline`                   | путь к `.timeline` (только animation)                                                                  |

Подробности растра и кодека — в [layers.md](layers.md).

## Что где лежит по смыслу

```text
Workspace (один .mgimg)
├── assets[]     → /assets + /previews/assets
├── videos[]     → /videos + /previews/videos
├── documents[]  → DocumentMeta в манифесте
│   ├── image      → только .tiles на слой
│   └── animation  → .tiles + .timeline на слой + Animation в манифесте
└── graphs[]     → /graphs/{id}.json
```

Метаданные документов и слоёв живут в манифесте; тяжёлые байты — в отдельных
записях архива. Undo/история правок в файл не пишется.

## Сохранение и загрузка

**Save (тот же путь):** сравнивает fingerprint/хэши с последним успешным
снимком (`SavedResources`). В архив уходят только изменившиеся assets,
layers, previews и манифест (если он изменился). Незагруженные
(deferred) записи копируются байт-в-байт без перекодирования.

**Save As / новый файл:** пишется полный набор записей; deferred-данные
читаются из прежнего снимка архива.

**Optimize:** компактит только уже сохранённую ревизию на диске.
Несохранённые правки в памяти не коммитит. Сырые слои (`compression`
отсутствует/`none`) сжимает в zstd и обновляет манифест.

**Open:** читает манифест и превью; полные пиксели документов/ассетов
остаются на диске (deferred) до активации документа или использования
ассета. Видео читается кусками из неизменяемого снимка архива.

Если на диске манифест изменился с момента последнего Save в эту сессию,
инкрементальный Save отказывается с ошибкой «Project was changed on disk».

## Версии схемы

| version | статус                                                             |
| ------- | ------------------------------------------------------------------ |
| 5, 6    | читаются; Optimize/Save могут сжать сырые слои и дописать previews |
| 7, 8, 9 | читаются                                                           |
| 10      | запись; graphs в манифесте                                         |

Несовместимый `format` или `version` — отказ открыть файл.
